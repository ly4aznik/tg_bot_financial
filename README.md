# Telegram Bot для учета трат

Проект поднимает Telegram-бота на базе `python-telegram-bot`, который принимает сообщение о расходе в свободной форме, извлекает сумму, описание, тип траты и дату через локальную LLM, валидирует данные через `pydantic` и только после подтверждения пользователем либо сохраняет запись, либо в тестовом режиме печатает ее в консоль.

## Что умеет бот

- принимает текст вроде `Вчера самокат 420`
- берет сегодняшнюю дату, если пользователь ее не указал
- использует явно указанный тип траты, если он есть в сообщении
- иначе просит локальную LLM определить тип траты по контексту
- валидирует трату через `pydantic`
- показывает пользователю распознанную запись и просит подтверждение
- в боевом режиме сохраняет запись в Google Sheets
- в тестовом режиме вместо записи печатает подтвержденную запись в консоль
- пишет аудит-лог взаимодействий в JSONL с действиями пользователя и метриками LLM

## Стек

- Telegram: `python-telegram-bot`
- Локальная LLM: любой OpenAI-compatible сервер с `POST /v1/responses`
- Валидация: `pydantic`
- Google Sheets: `gspread` + `google-auth`

- `Общепит/Доставка`

- `Одежда`

- `Продукты базовые`
- `Вкусности`
- `Другое`
- `Обед`
- `Обязательные платежи/Подписки`
- `Досуг`
- `Подарки`
- `Дом`
- `Транспорт`
- `Домашние животные`
- `Личные расходы`
- `Инвестиции`

В pydantic эти значения представлены как `StrEnum` `ExpenseType`, а модель траты содержит поля:

- `expense_type`
- `expense_date`
- `expense_amount`
- `expense_description`

## Подготовка

1. Создай Telegram-бота через BotFather и получи токен.
2. Подними локальный OpenAI-compatible сервер. Например, `llama.cpp` с HTTP-сервером, который поддерживает `POST /v1/responses`.

```bash
llama-server -m /path/to/model.gguf --port 8080
```

3. Для боевого режима создай сервисный аккаунт Google Cloud.
4. Включи Google Sheets API и Google Drive API.
5. Скачай JSON-ключ сервисного аккаунта и положи его, например, в `credentials/google-service-account.json`.
6. Создай Google-таблицу и поделись ею с email сервисного аккаунта.
7. Возьми `spreadsheet_id` из URL таблицы.

## Настройка окружения

1. Создай и активируй виртуальное окружение:

```bash
python -m venv .venv
.venv\Scripts\activate
```

2. Установи зависимости:

```bash
pip install -r requirements.txt
```

3. Создай `.env` на основе примера:

```bash
copy .env.example .env
```

4. Заполни `.env`:

```env
TELEGRAM_BOT_TOKEN=<YOUR_TELEGRAM_BOT_TOKEN>
GOOGLE_SERVICE_ACCOUNT_JSON=credentials/google-service-account.json
GOOGLE_SPREADSHEET_ID=<YOUR_GOOGLE_SPREADSHEET_ID>
GOOGLE_WORKSHEET_NAME=Expenses
OPENAI_COMPATIBLE_BASE_URL=http://localhost:8080
OPENAI_COMPATIBLE_MODEL=local-model
OPENAI_COMPATIBLE_API_KEY=
OPENAI_COMPATIBLE_REASONING_EFFORT=
BOT_TIMEZONE=Europe/Moscow
REQUEST_TIMEOUT_SECONDS=20
TEST_MODE=true
AUDIT_LOG_PATH=logs/interactions.jsonl
```

## Ограничение времени ответа модели

- `REQUEST_TIMEOUT_SECONDS`: жесткий лимит на ожидание ответа от модели в секундах. Если модель не успеет ответить за это время, бот вернет понятную ошибку.
- `OPENAI_COMPATIBLE_REASONING_EFFORT`: если endpoint поддерживает reasoning-настройки `Responses API`, бот отправит `reasoning.effort`. Допустимые значения: `none`, `minimal`, `low`, `medium`, `high`, `xhigh`.

Для задачи извлечения трат обычно стоит пробовать `none` или `minimal`.


## Аудит-лог

Бот пишет структурированный аудит-лог в файл `AUDIT_LOG_PATH` по умолчанию в `logs/interactions.jsonl`.

В лог попадают события:

- входящее сообщение пользователя
- распознанная трата
- текст сообщения, который бот показал пользователю
- согласие или отказ пользователя
- успешное сохранение или ошибка сохранения
- метрики вызова модели: `latency_ms`, `input_tokens`, `output_tokens`, `total_tokens`, `reasoning_tokens`

Формат лога — JSONL: одна строка = одно событие.
## Режимы работы

- `TEST_MODE=true`: после подтверждения бот не пишет в Google Sheets, а выводит подтвержденную запись в консоль приложения.
- `TEST_MODE=false`: после подтверждения бот пишет запись в Google Sheets. В этом режиме `GOOGLE_SERVICE_ACCOUNT_JSON` и `GOOGLE_SPREADSHEET_ID` обязательны.

## Запуск

```bash
python main.py
```

## Как теперь выглядит сценарий

1. Пользователь отправляет сообщение с тратой.
2. Бот показывает `Обрабатываю...`.
3. Бот распознает тип траты, дату траты, сумму траты и описание траты.
4. Бот показывает распознанную запись и спрашивает, все ли верно.
5. После этого пользователь может либо нажать кнопку, либо написать в чат исправление вроде `исправь сумму на 1000` или `поменяй категорию на Транспорт`.
6. Только после подтверждения запись либо уходит в Google Sheets, либо печатается в консоль в тестовом режиме.
7. Если нажать `Нет, отменить` или написать `нет`, запись не сохраняется.

## Формат Google Sheets

В боевом режиме бот читает данные из диапазона `B5:E` на выбранном листе и ищет первую пустую строку, чтобы записать новую трату без перезаписи существующих строк. Если данные уже вышли ниже строки 200, бот продолжит запись в `201`, `202` и дальше.

Ожидаемая структура листа:

- `B4` = `Дата`
- `C4` = `Сумма`
- `D4` = `Описание`
- `E4` = `Категория`

В новую строку бот записывает:

- дату траты
- сумму траты
- описание траты
- тип траты

Если заголовки в `B4:E4` не совпадают с ожидаемыми, бот остановит запись с ошибкой, чтобы не повредить данные.

## Примеры сообщений

- `650 обед`
- `Вчера самокат 420 тип: Транспорт`
- `05.04 линзы 523 тип: Здоровье/Медицина/Уход`
- `Дал в долг 5000 01.04`

## Важное допущение

Бот ожидает OpenAI-compatible endpoint с поддержкой `Responses API` на пути `/v1/responses`. Для строгого JSON в запрос отправляется `text.format = json_object`, а текст ответа читается из `output_text` или массива `output`.
